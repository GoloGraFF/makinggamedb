## Теория

### 1. Игра — программа, которая крутится по кругу

Любая игра десятки раз в секунду повторяет три шага:

1. **Ввод** — что нажал игрок?
2. **Обновление** — двигаем героя, проверяем столкновения, считаем урон.
3. **Отрисовка** — рисуем новый кадр.

Это **игровой цикл** (game loop). 60 повторов в секунду = 60 FPS. Аналогия — мультфильм в блокноте: при быстром перелистывании картинка «оживает».

### 2. Что такое движок

**Движок** — готовые детали (окно, отрисовка, звук, физика, ввод) плюс редактор. Задача разработчика — правила и содержимое.

Почему **Godot**:

- бесплатный и с открытым кодом (лицензия MIT), никаких отчислений;
- лёгкий (~100 МБ), работает на слабых ноутбуках;
- отлично подходит для 2D, умеет 3D;
- свой простой язык **GDScript**, похожий на Python.

```gdscript
extends Sprite2D

func _process(delta):
    # вызывается каждый кадр — это и есть игровой цикл
    position.x += 100 * delta  # 100 пикселей в секунду вправо
```

`_process` Godot вызывает каждый кадр. `delta` — время с прошлого кадра, благодаря ей скорость не зависит от FPS.

### 3. Ядро игры (core loop)

То, что игрок повторяет снова и снова:

- **Vampire Survivors:** ходишь → оружие само бьёт врагов → собираешь опыт → выбираешь улучшение → врагов больше.
- **Stardew Valley:** сажаешь → поливаешь → собираешь → продаёшь → покупаешь семена получше.
- **Mario:** бежишь → прыгаешь через препятствия → доходишь до флага.

Скучное ядро графика не спасёт → сначала **прототип** из квадратиков.

### 4. Кто делает игры

Роли в студии: геймдизайнер, программист, художник, звукорежиссёр/композитор, тестировщик, продюсер/маркетолог. **Соло-разработчик** понемногу выполняет все.

Примеры: Stardew Valley (Эрик Бароне, ~4,5 года), Undertale (Тоби Фокс), Papers, Please (Лукас Поуп), первые версии Vampire Survivors (poncle).

Главный секрет — **маленький масштаб**: доводить до конца маленькие игры (день → неделя → месяц).

### 5. Проект в Godot

- **Проект** — папка с файлом `project.godot`.
- **Сцена** — кусочек игры (уровень, герой, пуля, меню), файл `.tscn`.
- **Узел (node)** — кирпичик сцены: `Sprite2D` (картинка), `Label` (текст), `Camera2D` (камера).
- Узлы складываются в **дерево**: корневой узел и дочерние.

Аналогия: проект — коробка LEGO, сцена — собранная модель, узлы — детальки.

## Практика: ставим Godot и запускаем первую сцену

1. **Скачать Godot 4.7** — <https://godotengine.org/download/> (Windows: <https://godotengine.org/download/windows/>). Стандартная версия, не .NET (актуальна 4.7.2). Установщика нет: распаковать в `C:\Godot\` и запустить `Godot_v4.7.2-stable_win64.exe`.
2. **Папка проектов** — `GameDev\Projects`, имена латиницей без пробелов.
3. **Проект** — Create → `lesson01_hello` → путь `GameDev\Projects` → Renderer **Forward+** (на слабом ПК — Compatibility) → Create & Edit.
4. **Сцена** — 2D Scene → переименовать корень в `Main` → Add Child Node (Ctrl+A) → `Label` → Text: `Привет, Godot! Меня зовут Данил.` → передвинуть внутрь синей рамки.
5. **Картинка** — перетащить `icon.svg` из FileSystem в сцену (создастся `Sprite2D`).
6. **Сохранить и запустить** — Ctrl+S → `main.tscn` → F5 → Select Current.

**Проверка:** дерево `Main` → `Label`, `Icon`; проект открывается после перезапуска Godot; F5 запускает игру без вопроса о главной сцене.

**Если что-то не так:** надпись не видна → она вне синей рамки; Windows ругается → «Подробнее» → «Выполнить в любом случае»; ошибка OpenGL/Vulkan → рендерер Compatibility или обновить драйверы.
