# Команды

## git clone

Команда которая скачивает удаленный репозиторий, историю изменений, создает локальную папку, настроит **origin**, создаст локальную ветку.

``` bash
git clone <ссылка на репозиторий>
```

## git status

показывает:
- текущую ветку
- измененные файлы
- добавленные в **staging** файлы
- неотслеживаемые файлы
- информация о том, опережает ли локальная ветка удаленную

## git add

добавляет изменения в **staging area**.

```bash
git add <file> #Добавить 1 файл
git add <file1> <file2> # Добавить несколько файлов
git add . # Добавить все файлы из текущей дериктории
git add -A # добавить все измененные файлы
```

> [!Warning]
> ==git add== не создает **commit**! Он только помещает данные о файлах в область которая будет добавлена в следующий **commit**.

Зачем вообще команда `git add`?

например:

```bash
#создаем файл1 файл2
#но хотил добавить в комит только файл 1
#поэтому

git add <file1>
git commit -m "добавили файл 1"

#файл1 будет закомичен, но файл2 не будет
```


## git commit

Создает коммит.

```bash
git commit -m "Коментарий к коммиту"
```

> [!INFO]
> **Коммит (commit)** - это состояние проекта на определенный момент времени.

Каждый коммит имеет уникальный идентификатор (**a84f92c**).

Коммит содержит:
- Автора
- дату
- сообщение
- ссылку на родительский коммит
- состояние файлов

Что происходит когда делаешь `git commit`?

```bash
echo "text" > text.txt
git add text.txt
git commit -m "Add file text.txt"
```
